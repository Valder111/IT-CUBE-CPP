## Динамическая память в C++ (`new` / `delete`)

В C++ существует два основных способа выделения памяти:

- **Статическое/автоматическое** — переменные создаются на стеке, их размер и время жизни известны на этапе компиляции.
- **Динамическое** — память запрашивается во время выполнения программы из так называемой **кучи (heap)**. Это позволяет работать с данными, размер которых неизвестен заранее.

### Операторы `new` и `delete`

- `new` — выделяет память под один объект или массив и возвращает указатель на начало этой памяти.
- `delete` — освобождает память, выделенную через `new`.
- `new[]` / `delete[]` — используются для выделения и освобождения **массивов**.

### Динамические переменные

Память можно выделять не только под массивы, но и под **одиночные переменные**:

```cpp
int* p = new int;     // выделили память под одно целое число
*p = 42;              // записали значение
cout << *p;      // прочитали значение

delete p;             // освободили память
p = nullptr;          // хорошая практика — обнулить указатель
```

Такой подход редко используется для простых типов, но может быть полезен при работе с объектами, создаваемыми по условию или передаваемыми между функциями.

### Динамические массивы

Если заранее неизвестно, сколько элементов понадобится (например, пользователь сам вводит размер), обычный массив (`int arr[100]`) не подходит. В этом случае:

```cpp
int size;
cout << "Введите размер: ";
cin >> size;

int* dynamicArray = new int[size];  // выделяем память под size элементов
```

Теперь `dynamicArray` ведёт себя как обычный массив: можно использовать индексацию (`dynamicArray[i]`).

**Важно!** После работы с динамическим массивом его **обязательно** нужно удалить:

```cpp
delete[] dynamicArray;  // [] говорит компилятору: это массив!
dynamicArray = nullptr; // хорошая практика — обнулить указатель
```

### Опасности и правила

1. **Утечка памяти** — если забыть вызвать `delete`, память останется занятой до конца работы программы. Это особенно опасно, если работать с динамической памятью в большом объёме, или держать вашу программу "в процессах" долгое время.
2. **Двойное удаление** — вызов `delete` дважды на один и тот же указатель приводит к неопределённому поведению (получаемые странности зависят от компилятора языка, вашей ОС и т.д.). Нужно быть внимательным!
3. **Использование после удаления** — обращение к памяти после `delete` — 100% ошибка, т.к. память уже очищена.
4. **Несоответствие `new`/`delete` и `new[]`/`delete[]`** — нельзя удалять массив через `delete` (без `[]`) и наоборот.

> **Важно** В современном C++ предпочтительно использовать «умные указатели» (`std::unique_ptr`, `std::shared_ptr`) и уже нам знакомый контейнер (`std::vector`), которые автоматически управляют памятью и исключают большинство ошибок.

### Пример грамотного использования

```cpp
#include <iostream>

int main() {
    int n;
    cin >> n;
    
    if (n <= 0) return 1;

    int* data = new int[n];
    
    for (int i = 0; i < n; ++i) {
        data[i] = i * i;
    }

    // ... работа с данными ...

    delete[] data;  // корректное освобождение
    data = nullptr; // защита от случайного повторного использования
    
    return 0;
}
```
